# Development guide

The rules, decisions and commands for everyone working on this repository. Nothing here assumes that one person decides for the team.

- Setting up a machine, the corpus and the models: [ONBOARDING.md](ONBOARDING.md).
- Who does which experiment, and how it is recorded: [CONTRIBUTIONS.md](CONTRIBUTIONS.md).

## Project

A local RAG pipeline over **public Dutch business documents** for staffing, secondment and technical companies: uitzend-cao's (ABU, NBBU), sector cao's (Metaal en Techniek, Metalektro), legislation (Wtta, Waadi, Arbeidstijdenwet, ...), the Belastingdienst model agreements, privacy guidance for recruitment and published government contracts. It is a BUas group challenge by Roef, Rutger and Lucan, each with one clearly identifiable experiment (docs/CONTRIBUTIONS.md), and a demo for companies. The code started as a copy of an earlier client pipeline; its rules, decisions and invariants below carry over unless this file says otherwise. The parse pass reads `*.pdf` only. `src/companydocs_rag/` has eight subpackages and `pyproject.toml` eight commands, in pipeline order:

`companydocs-parse-pass` → `companydocs-normalize` → `companydocs-chunk` → `companydocs-index` → `companydocs-search` / `companydocs-answer` / `companydocs-demo`

`companydocs-metadata` reads the chunk files beside that chain, and nothing outside it reads its output: the index reads only chunk files, retrieval only the index. Default paths resolve against the project root (the folder with `pyproject.toml`). Flags relocate most of them (`--help`); the log folders are settings (`log_dir`), and the demo's `data/raw/` and type override file have no flag.

### Packages

- `ingestion/`: the parse pass, OCR and normalization.
  - `extraction.py` (per-page text via pdfplumber), `type_detection.py` (keyword scoring for four types, else `unknown/other`; weak on this corpus, and nothing downstream uses `detected_type`) and `structure.py` (an interim structure check the chunker does not use, decision 2; its column-aligned field-label pattern can never match the current extraction, which an `xfail(strict=True)` test pins).
  - `quality.py`: per page the source (`native`/`no_text_layer`, from character count alone against `MIN_CHARS_NATIVE_PAGE`), the tier (Clean/Decent/Garbage, only for pages with a text layer, from text-reliability signals only) and `text_origin` (`native`/`ocr`/`none`); per document a reporting label (`MAX_GARBAGE_PAGE_RATIO_DOCUMENT`, strictly greater than, never worst-tier-wins; routing is per page). Image coverage, preocr's `needs_ocr` and the structure score are evidence and decide nothing. preocr is imported only inside the functions that call it, so importing the package never loads python-magic (known issue); keep it that way.
  - `ocr.py`: a page without a text layer (whose extraction did not fail) goes to OCR: rendered with pypdfium2 (300 dpi, grayscale), read by Tesseract. OCR text gets no tier; its confidence is evidence, without a threshold. The cache (`data/interim/ocr_cache/`) is keyed on cache format version, file sha256, page, dpi, grayscale, language and Tesseract version; bump `CACHE_FORMAT_VERSION` when the entry format, the Tesseract invocation or the pypdfium2 pin changes.
  - `language.py`: one language per document, no detection: `data/manual/language_overrides.csv`, then the corpus index `00_INDEX.csv` in the PDF's nearest ancestor folder, then `nld` with a WARNING.
  - `parse_pass.py`, `cli.py`: `classify_and_assess(path)` returns the document `status` (`processed`/`failed`; a failed document has no tier), the type, the per-page axes, the document tier, the explanation, every signal and the page text store record (`schema_version` 2). `companydocs-parse-pass <folder>` (`-r` for subfolders) writes, under `data/interim/`, the CSV report, the result per document except its page text (`parse_pass_signals/`, a default output) and the page text store (`page_text/`), both mirroring the input folder, and the OCR cache.
  - `normalization.py`, `normalize_cli.py`: `companydocs-normalize` turns the page text store into one file per document under `data/interim/normalized/`: each page soft-normalized, with every removed line and every join recorded. A store `schema_version` other than 2 is refused (rerun the parse pass). The page-label regexes and conjunction lists live only in the YAML (`ingestion.normalization`). `hard_normalize`, for BM25 and queries, is never applied to this output.
  - `settings.py`: loads `config/settings.yaml` (Settings, below).
- `chunking/`: `companydocs-chunk` turns the normalized files into one chunk file per document under `data/interim/chunks/`; a `schema_version` other than 1 is refused (rerun `companydocs-normalize`). The route is chosen per document (decision 2): `structured` when a numbering run is accepted (its sections become chunks, the rest goes through a line-based splitter), else `generic`. Each chunk is an unchanged slice of the document's non-empty page texts joined with a line feed, with per-page provenance (`page_spans`).
- `embeddings/`: `compose_embedding_text` (clause label, line feed, text; or the text alone) is the only text both vectors are computed from, and it is never stored. `dense.py`: Qwen/Qwen3-Embedding-0.6B at a pinned revision, on CPU in float32, `trust_remote_code=False`, the query instruction for queries only; it imports sentence-transformers, and so torch, only when the embedder is constructed (subprocess tests check this; keep it that way). It also holds the settings helpers (`SettingsError`, `setting_*`) that retrieval, answering, metadata and the interface use. `sparse.py`: terms from `tokenize(hard_normalize(text))` (letter and digit runs plus one composite token for numbers such as 8.9 or 31-12-2024; no stemming, no stopwords), term ids from sha256, BM25 values; Qdrant applies IDF. A change to `hard_normalize` requires bumping `TOKENIZER_VERSION`; a contract test in `tests/embeddings/` pins its output.
- `vectorstore/`: `companydocs-index` rebuilds the whole index at `data/processed/index/` from every chunk file: one Qdrant local-mode collection with a dense and a BM25 sparse vector per chunk, and `manifest.json` (model, versions, BM25 values, every chunk file's sha256). A refused or invalid chunk file, a duplicate chunk id or a text over the token limit means no index is written; a non-empty folder without `manifest.json` is never replaced. It builds in `<index-dir>.building`, writes `manifest.json` last, then swaps the new index in. `store.py` is the only module that opens Qdrant. The command downloads the embedding model (about 1.2 GB) into the Hugging Face cache, outside the repository, when it is missing.
- `retrieval/`: `companydocs-search "<query>"` (`--json`) wraps `Retriever`, which the answer layer calls in-process. It reads the index and its manifest only and never downloads the model. Eight manifest keys (`manifest_version`, `model_name`, `model_revision`, `embedding_text_version`, `tokenizer_version`, `term_hash`, `bm25_k1`, `bm25_b`) must equal the current settings and code constants, else the index is unusable (rebuild it). The dense and the sparse leg are queried separately (50 each) and fused by reciprocal rank fusion in project code (k 60, 20 candidates); each candidate keeps both legs' ranks and scores. There is no relevance threshold.
- `answering/`: `companydocs-answer "<question>"` or `--questions <file>` (a CSV with `question_id` and `question`; `--selection-mode`, `--json`) wraps `Answerer`, the in-process API the demo also uses. `Answerer` keeps one `Retriever` open, selects chunks (`fused`, the default, or `per_path`) within a character budget, and asks the LLM through an OpenAI-compatible `/chat/completions` endpoint with httpx, without retries (Ollama on localhost by default). A source enters the prompt as `[n]` with a document number, its language, pages and text; never a file name, clause label or provenance. It flags a prompt the server probably cut (characters per `prompt_tokens`), maps the cited `[n]` back to chunks and their pages, and abstains on the model's `ONVOLDOENDE BEWIJS`, on zero candidates or on the optional `min_dense_score` gate (off). Each answer, with its full prompt, is one JSONL record in `data/processed/answer_logs/`, one file per `Answerer`. System prompt: `config/prompts/answer_system_nl.txt`; Ollama Modelfiles: `config/ollama/`.
- `metadata/`, a limited prototype built for lease contracts (its `lease_family_types` do not occur in this corpus, so `extract` finds nothing in scope until they are adapted): `companydocs-metadata extract` types each chunked document (`data/manual/document_type_overrides.csv`, else the corpus index), reads `amends`/`duplicate_of` relations from `data/manual/relations.csv`, and for the types in `lease_family_types` (Huurovereenkomst, Allonge, Lease- / exploitatieovereenkomst) asks the LLM, through the answer layer's `GeneratorClient`, for six date and term fields plus other termination provisions, checking every quote against its chunk. It writes one extraction file per chunk file (`data/processed/metadata/extracted/`) and one JSONL log per run (`data/processed/metadata_logs/`). Keywords exist for `nld` and `eng` only; a chunk `schema_version` other than 1 is refused. `report --reference-date YYYY-MM-DD` writes the Dutch follow-up overview (`followup.md`, `.json`, `.csv` in `data/processed/metadata/`): per document the expiry date, next renewal date and latest notice date, computed in code; it reads no clock and needs neither Ollama nor the index. Only the extraction modules import the generator client, and only when `extract` runs. System prompt: `config/prompts/metadata_extract_system.txt`.
- `interface/`: `companydocs-demo` (`--port`, `--index-dir`) is a local, single-user browser interface over `Answerer` at `http://127.0.0.1:8765/`: `http.server` without threads, bound exclusively to 127.0.0.1, one inline page under a Content-Security-Policy, and one `Answerer`, warmed up at the start, for the server's life. Each question stands alone (no conversation memory). An `answered` result gets a card per cited source: the document type (`metadata.doctype`, else "type onbekend"), the file name, the clause label as a hint, and per page a provenance label and a link that renders the page of the PDF under `data/raw/` as a PNG in memory, by file hash and page number, re-hashed each time. It prints the URL as its only stdout line and opens no browser; a generator failure while serving is a message on that question.

### Exit codes

Each CLI module's docstring says what each code covers; 2 includes argparse's usage errors.

| command | 0 | 1 | 2 | 3 | 4 |
|---|---|---|---|---|---|
| `companydocs-parse-pass` | done, also when documents failed | | the folder is not a folder | | |
| `companydocs-normalize`, `companydocs-chunk` | every file written | a file refused or failed (the others are written) | cannot start: no such folder, invalid settings | | |
| `companydocs-index` | index in place | not written; the previous index unchanged | cannot start | | |
| `companydocs-search` | done, also with zero candidates | index unusable: a manifest key differs, another process holds it, or the model is not in the local cache | cannot start | | |
| `companydocs-answer` | done, no record in status `error` | index unusable | cannot start | generator unavailable; wins over 4 | done, with a record in status `error` |
| `companydocs-metadata extract` | done, no document `partial` or `error` | chunk folder missing or a chunk file refused; nothing written | cannot start, also on a malformed override or relations file | generator unreachable, model unknown or warm-up failed | done, with a document `partial` or `error` |
| `companydocs-metadata report` | done | extraction folder missing or empty, or a file refused; nothing written | bad arguments or settings | | |
| `companydocs-demo` | stopped with Ctrl+C | index unusable or held | cannot start, also when the port is taken | generator unavailable at warm-up | |

## Data

Pipeline data moves through `data/raw/` → `data/interim/` → `data/processed/`. The public PDFs in `data/raw/` and its index are tracked in git; everything else under `data/` and `scratch/` is git-ignored (only the `.gitkeep` files are tracked), so never commit derived data. Every document is defined in `corpus/sources.csv` (one row per document: id, domain, title, publisher, version, URL, sha256, pages, reuse note).

- `data/raw/`: the 26 public PDFs (in git) and, after `--with-demo-only`, the two demo-only SNA documents in `data/raw/demo-only/` with their own index (git-ignored, copyright reserved; leave them out of the evaluation index). `scripts/download_corpus.py` checks what is in place and downloads what is missing: it refuses a file whose sha256 differs from `corpus/sources.csv`, stores it as `data/raw/<domain>/<id>.pdf` and writes the index `data/raw/00_INDEX.csv` (`Map;Bestandsnaam;Taal;Documenttype`, the domain as the type). Never edit `data/raw/` by hand; change `corpus/sources.csv` and rerun the script.
- `data/manual/`: optional hand-kept overrides (`language_overrides.csv`, `document_type_overrides.csv`, `relations.csv`). A missing one is an INFO line, not an error; an unreadable or malformed type override or relations file is exit 2.
- `data/interim/`: `parse_pass_report.csv`, `parse_pass_signals/`, `ocr_cache/`, `page_text/`, `normalized/`, `chunks/`. `data/processed/`: `index/`, `answer_logs/`, `metadata/`, `metadata_logs/`. Paths inside them are relative to the project root.
- `evaluation/`: the shared question set (`questions.csv`: question id, question, expected source id(s) and page(s), author) and the evaluation results that the contributions report. It is committed: the documents are public.
- `scratch/`: throwaway scripts and notes, git-ignored.

## Settings

`config/settings.yaml` holds the pipeline configuration, one top-level section per stage, in this order: `ingestion` (`parse_pass`: `quality`, `type_detection`, `structure`, `ocr`, `language`; then `normalization`), `chunking`, `embeddings`, `interface`, `answering`, `metadata`, `retrieval`. Every value also has a Python default, except the type definitions and the normalization label regexes and conjunction lists, which live only in the YAML. The tuning data of `quality`, `type_detection` and `structure` are first versions, not validated on the real documents (the file's header). `COMPANYDOCS_RAG_SETTINGS` names a file that replaces the whole file; when that file does not exist, nothing is read and every section silently takes its Python defaults (normalize then exits 2, type detection reports `unknown/other`).

Tests read the committed file and constrain it:

- Order: `interface` sits between `embeddings` and `answering`, `metadata` between `answering` and `retrieval`, and a retrieval test reads from `retrieval:` to the end of the file, so a new section goes before `retrieval` or its change adapts that test.
- The keys of `chunking`, `embeddings`, `retrieval`, `answering`, `interface` and `metadata` must be in order and equal the Python defaults; tests also pin the values of `chunking`, `ingestion.normalization`, `answering`, `interface` and `metadata`, and the comment text of `embeddings`, `retrieval`, `answering`, `interface` and `metadata`. Changing such a value means changing the YAML, the default and the test together; to try a value, point `COMPANYDOCS_RAG_SETTINGS` at a copy.
- Tests in `tests/ingestion/` read the `ingestion` section from the committed file; `test_preocr_contract.py` checks `min_chars_native_page` against preocr's short-text cut-off.

## Environment and commands

- Windows, with Windows PowerShell 5.1 for `scripts/run-tests.ps1`. Python `>=3.11`; the local `.venv` is uv-managed (CPython 3.12) with the package installed in editable mode, so `import companydocs_rag` resolves to `src/`. `uv.lock` is committed and current; `uv sync` (and `uv run`) is safe to use. `.gitattributes` forces LF line endings.
- Run tests from the repository root: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-tests.ps1`; pytest arguments are passed on (single test: `powershell -NoProfile -ExecutionPolicy Bypass -File scripts/run-tests.ps1 tests/ingestion/test_foo.py::test_bar`). In its own process the script removes every PATH entry containing `Git\usr\bin` (known issue below), checks that `uv` and `tesseract` are on PATH, runs `uv run pytest` and exits with pytest's code; its own codes are 90 (PATH empty after the removal), 91 (no `uv`), 92 (no `tesseract`) and 5, with its own message, when pytest collects no tests.
- Run the commands in pipeline order with `uv run <command>` (or `.venv/Scripts/<command>`). One process at a time on the index: Qdrant local mode locks the index folder, so `companydocs-index`, `-search`, `-answer` and `-demo` run one after another; `companydocs-answer` and `companydocs-demo` hold the index for their whole run, and on Windows `companydocs-index` cannot replace an index another process holds open. `companydocs-metadata extract` takes no index lock but shares Ollama with `companydocs-answer` and `companydocs-demo`, so do not run them at the same time; `report` needs neither.
- Lint and format with ruff (a `dev` dependency group; config in `pyproject.toml`): `.venv/Scripts/ruff check .` and `.venv/Scripts/ruff format .` (`ruff format --check .` verifies without writing).
- `pyproject.toml` declares ten runtime dependencies: `httpx`, `pdfplumber` and `pyyaml` with lower bounds; `pillow`, `preocr`, `pypdfium2`, `qdrant-client`, `sentence-transformers`, `torch` (from PyPI, the CPU build on Windows) and `transformers` pinned with `==`. preocr pulls in `python-magic` (known issue) and others; the `dev` group has `pytest` and `ruff`. When code starts importing a new package, add it to `pyproject.toml` in the same change; two hygiene tests (`tests/interface/`, `tests/metadata/`) pin the number of runtime dependencies at 10, so that change updates both, and `tests/vectorstore/test_packaging.py` requires the qdrant-client, sentence-transformers, transformers and torch pins to equal the installed versions.
- `preocr` is pinned exactly (`==1.11.0`) because the pipeline depends on a private preocr function; an upgrade means bumping the pin and re-deriving the contract test's values (`tests/ingestion/test_preocr_contract.py`) deliberately.
- Tesseract 5.5.3 is a system binary on PATH with ces deu eng fra nld pol slk, not managed by uv.
- Ollama is a local inference server on localhost (`http://127.0.0.1:11434/v1`), not managed by uv, needed by `companydocs-answer`, `companydocs-metadata extract` and `companydocs-demo`. No version is pinned and no artifact records one. A team member pulls the base model and creates the 8k model from `config/ollama/` by hand (README, Ollama models); no script does that.
- No code reads `.env`, although the settings header and the `ingestion/settings.py` docstring say so. An API key would come from the variable that `answering.api_key_env` or `metadata.api_key_env` names; both are null. The generator client is built with `trust_env=False`, so it ignores proxy and certificate variables (`HTTP_PROXY`, `SSL_CERT_FILE`, ...). `companydocs-index` contacts the Hugging Face Hub on every run unless `HF_HUB_OFFLINE=1` is set in that terminal.
- **Known issue:** if pytest or the parse pass hangs, or crashes with an access violation, the first time something calls into preocr (never during collection, since no test module imports preocr at load time), check whether `Git\usr\bin` is on PATH in that shell: python-magic then loads an incompatible libmagic that fails inside native CPython. It is not on a normal Windows PATH, but it is on the PATH of Git Bash. `scripts/run-tests.ps1` removes those entries in its own process, so run the tests through it, and run the parse pass from PowerShell. `companydocs-normalize` does not load preocr.

## Tests

- Tests mirror the source layout (`tests/ingestion/`, ...), plus `tests/scripts/` for `scripts/run-tests.ps1` (Windows only). No test reads or writes under `data/`; fixtures are fabricated, and a few tests check only the shape of default paths.
- `tests/answering/`, `tests/metadata/` and `tests/interface/` send requests only through `httpx.MockTransport` (with a fake Retriever where one is needed); a guard in each folder fails any other request (in `tests/interface/`, any socket except the server under test), and `COMPANYDOCS_RAG_SETTINGS` points at a file in `tmp_path`.
- `test_lazy_imports.py` in `tests/{chunking,embeddings,ingestion,retrieval,vectorstore}/` checks in a subprocess that importing a package loads no model library and no preocr; the hygiene tests check imports, ASCII-only sources and string escapes. A new import in a shared module can fail tests in another package's folder.
- Tests in `tests/ingestion/` run on inline fabricated text built with `_helpers.py`; the only PDFs are generated in tests from a Pillow image. Every test that goes through `assess_quality` or `assess_pages` runs preocr's private text-quality function for real, per page, via `_page_quality`, so it imports preocr, which tries python-magic: on a normal PATH that import fails and preocr falls back to mimetypes; with `Git\usr\bin` on PATH it hangs or crashes. `test_preocr_contract.py` calls the private function directly.
- `tests/answering/test_files.py` pins the README's Ollama models section (four exact strings) and checks that this file names the answering stage; the Modelfiles and both prompt files are pinned byte for byte.

## Data and privacy

- The corpus is public: government publications (reusable under art. 15b Auteurswet unless reserved), cao texts published by the cao parties, and guidance published by the Belastingdienst and others. `corpus/sources.csv` records the reuse note per document. A document with its own copyright notice is marked `demo-only` there and is left out of the submission and the evaluation. Documents of a specific company (privacy statements, contracts, internal documents) are not part of the corpus.
- Published government contracts can contain names of officials or suppliers' staff. Do not copy personal data into code, tests, the question set, commit messages or a chat; refer to the clause, not the person.
- The pipeline stays local (Project rules) because the demo is meant for companies' own, non-public documents later.

## Project rules

These are hard rules for every change; whoever reviews a pull request checks them. A review finding that recurs becomes a rule here.

- **Everything runs locally.** No cloud APIs, not for embeddings, not for OCR, not for the LLM. Model weights may be downloaded once; inference runs on the developer's own machine, and a local inference server on localhost (such as Ollama) counts as local. If a solution requires an external API, propose it but do not implement it.
- **Only public documents enter the repository**: the PDFs in `data/raw/` whose `include` is `yes` in `corpus/sources.csv`, never a `demo-only` one and never a document of a specific company. Test fixtures use fabricated text; the question set may quote short phrases of a clause where a question needs it.
- **Documents are primarily Dutch**, with some other languages. Every tokenizer, model or parser choice must be checked against that.
- **Never silently skip a pipeline step on a malformed document.** Failure is explicit: log it, flag it, continue with the rest.
- **Non-ASCII in Python is written as `chr()`.** In source and tests, including regex patterns, write every non-ASCII or invisible character in a str as `chr(0x...)` or `unicodedata.lookup("NAME")`, never as a literal and never as a `\u`, `\U`, `\N{}` or `\x` escape, so that there is one notation and no invisible character in the source. `\n`, `\r` and `\t` are fine; bytes literals may use `\x`. In comments and docstrings, name the character (U+00A7 SECTION SIGN). Visible literals in `config/settings.yaml` are fine. Older lines predate this rule: the literals in `structure.py`, `test_parse_pass.py`, `test_quality.py` and `test_preocr_contract.py`, and the `\x07` escape in `test_preocr_contract.py`. Leave them unless a spec says otherwise (spec 004 review F6).
- **`data/raw/` changes only through `corpus/sources.csv` and `scripts/download_corpus.py`**, never by hand, and `data/manual/` only by people. Derived artifacts go to `data/interim/` and `data/processed/`.
- **Refer to a document by its source id** from `corpus/sources.csv` (for example `cao-abu-2026`), in code comments, specs, the question set and reports.

## Architecture decisions

These decisions are the **baseline**. An experiment may test an alternative to one of them (that is what the contributions are for), but it adds the alternative behind a setting or a flag and leaves the baseline the default; changing the default needs the evaluation result and a team decision (Working together).

1. **Quality classification before chunking**, per page, not per document: text layer vs no text layer, and text reliability. Pages are routed on those. Template consistency (the structure score) is deliberately not part of this: structure is a document-level property and must not gate a per-page decision (spec 001). It is still computed and recorded as evidence; no step uses it (see decision 2).
2. **Structure-aware chunking** on article and clause numbering, not fixed token length. The chunker selects its route per document from its own heading recognition: headings count only when they form a valid ascending numbering run that passes the acceptance checks; otherwise the generic route is used and marked as such. Neither the structure score nor the quality tier selects the route; the tier travels with each chunk as provenance (structure decides where to cut, tier how much to trust the result). The chunker takes a `structure_hint` input reserved for a later detector; its only value is `unknown`, meaning no external opinion. `structure.py` is not used by the chunker.
3. **Metadata outweighs the embedding model.** Clause labels and short clause summaries have the highest return.
4. **Hybrid retrieval is mandatory** (semantic + keyword). Pure vector search fails on exact queries: amounts, dates, article references.
5. **Relationships between documents are modelled explicitly**: amendments, annexes, cross-references.

## Design invariants

What must not shift, beyond the rules and decisions above.

- **`source` is never extended.** It keeps `native` and `no_text_layer`; a third value would fall silently through the equality filters in `quality.py`. A new concept gets a new field, as `text_origin` did.
- **Provenance is not quality.** `text_origin` says how to check a source, not whether it is right; a quality statement comes from calibration, not from provenance.
- **The page text store is the only input after OCR.** Later steps never reopen a PDF; what they need from the parse pass belongs in the store. The normalized files derive from it and are the chunker's input. One exception: the demo opens the original PDF read-only to show a page, requested by file hash and page number and re-hashed first; never for text, never by a path from the browser. Provenance (`text_origin`, tier, OCR confidence, page number, file hash) travels per page into each chunk and on to the source references in the answer result, the log and the interface, never into the prompt to the LLM.
- **No threshold without calibration data.** Thresholds are named constants in `config/settings.yaml`, not inline numbers; where a probe measured a value, it stands as a comment beside the constant.
- **No pattern without a detector.** Structure seen in some documents is a hypothesis, not a property of a document family. A parser that relies on a pattern detects it itself and falls back, marked, to the generic route when it is absent. No structure-driven route without that fallback; when in doubt, the generic route.
- **Formatting noise is not text unreliability.** Dot leaders, fillers and extraction artefacts are categories of their own with their own evidence, not a quality signal.
- **Normalization and chunking change encoding and layout, never content.** No character correction, no restoring "11" to "1.1" or `$` to the section sign, no merging lines into paragraphs, no hyphen repair across a page boundary. The one exception: a word hyphenated at a line end within one page is joined, and every join is recorded. What is removed (now only page labels and page-number runs) stays recorded per page with its line index, edge, reason and family or offset.
- **File names are not a signal**: not for signing status, document type or language. A file name as a lookup key (corpus index, override files) or shown on a source card is not a signal; a document header in a prompt comes from metadata, not from the file name.
- **Evidence is kept beside the labels.** It keeps almost every analysis that was cut possible later without rerunning the pipeline.
- **Corrections to merged specs land as new specs**, not by reopening a merged one.
- **Measure on held-out questions and regressions.** A measure tuned on the question set is also measured on questions not used for tuning, and checked for regressions elsewhere in the set.

## Working together

- Work on your own branch (`roef/...`, `rutger/...`, `lucan/...`), merge into `main` through a pull request, and never push to `main` directly. Do not rewrite history on `main`. The pull requests are the evidence of who did what, so a PR holds one person's work.
- Each person's experiment lives in `experiments/<name>/` (README with question, change, setup, result; the config used; the result files) and is summarised in docs/CONTRIBUTIONS.md. Code changes for an experiment go in `src/` behind a setting or flag, with tests.
- A change larger than a small fix leaves a note in `specs/` under the next free number: a full spec from `specs/TEMPLATE.md`, or a short change note with the goal, what changed, how it was tested and what was left.
- Changing a project rule, an architecture decision or a design invariant is a team decision: propose it, agree on it as a team, then record it here.
- The shared question set `evaluation/questions.csv` is the evaluation baseline: every experiment reports its effect on it against the baseline configuration, on the same commit of the corpus.
